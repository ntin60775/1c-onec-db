# 1c-onec-db

pytest-фикстуры для тестов **уровня логики 1С** контура [1C-DSH](https://github.com/ntin60775/1C-DSH):
тонкий MCP-клиент `onec_db` (execute_code / execute_query через [1c-mcp-toolkit](https://github.com/ROCTUP/1c-mcp-toolkit))
и HTTP-заглушка внешних систем `stub_server`. Только stdlib — ноль pip-зависимостей.

Это то, чем заменяется юнит-наследие (yAxUnit): инварианты модулей, расчёты,
проверки заполнения — обычные pytest-тесты, вызов логики через BSL на тестовой базе.

## Установка

```bash
pip install git+https://github.com/ntin60775/1c-onec-db.git@v0.1.0
```

Пакет — pytest-плагин (entry-point `pytest11`): фикстуры `onec_db`,
`solo_base` и `stub_server` доступны во всех тестах проекта сразу,
conftest не нужен. С master идут (wheel-релиз v0.1.6 их ещё не несёт, пин
установки обновит поставка плагина): фикстура `solo_base`, финализация
сеанса, канонная раскладка контура (`.dsh/1c`, скрипты пакета) и диагностика
канала в ошибке `onec_db`.

## Фикстуры

```python
import json

def test_сумма_ндс(onec_db, json):
    data = onec_db.execute("""
        Результат = ЗаписатьJSON(Новый ЗаписьJSON, Расчёты.СуммаНДС(62000));
    """)
    assert json.loads(data) == 10333.34

def test_создание_контрагента(onec_db):
    obj = onec_db.create_object("Контрагенты", {"Наименование": "МокТест", "ИНН": "7700000000"})
    try:
        rows = onec_db.query('ВЫБРАТЬ Код ИЗ Справочник.Контрагенты ГДЕ Наименование = "Е2Е-МокТест"')
        assert rows["data"], "контрагент не найден"
    finally:
        onec_db.delete_object(obj["type"], obj["guid"])

def test_интеграция_с_заглушкой(onec_db, stub_server):
    stub_server.route("POST", "/api/bid", 200, '{"status": "ok"}')
    onec_db.set_constant("АдресСервисаЗаявок", stub_server.url)  # канон мока: URL из константы
    # ... вызов логики, которая ходит в сервис ...
    assert ("POST", "/api/bid") in [tuple(c.values()) for c in stub_server.calls]
```

## Контракты

- **execute_code**: BSL выполняется на сервере тестовой базы; результат читается
  из переменной `Результат`, которую код обязан установить. Сложные значения —
  `ЗаписатьJSON` (`execute_json` вернёт python-объект). Сериализатор тулкита
  отдаёт значения строкой: строки — JSON-литералом, коллекции — JSON;
  клиент распаковывает валидный JSON, остальное возвращает строкой как есть.
- **create_object/delete_object**: только менеджерный путь
  (`Справочники.X.СоздатьЭлемент()`); `Новый(Тип("СправочникОбъект.X"))` в
  окружении `Выполнить` тулкита ломает установку реквизитов («Элемент не
  выбран»). Генерируемые переменные носят префикс `Е2Е` — имя `Объект`
  резолвится в реквизит формы обработки. Данные помечаются маркером `Е2Е-`.
- **URL 1c-db**: env `ONEC_DB_URL` → `contour.json` канонной раскладки
  (`.dsh/1c`, затем промежуточная `.dsh`; локальный оверлей
  `contour.local.json` — фактический порт мультистенда) →
  `http://127.0.0.1:6003/mcp`. Нечитаемый вход назван в stderr, тихого
  фолбэка на чужой стенд нет.
- **Проба принадлежности**: фикстура `onec_db` сверяет базу прокси
  (`СтрокаСоединенияИнформационнойБазы()`) с привязкой дерева из local-слоя
  (`infobases.origin.connection`; `File=` / `Srvr+Ref`). Рассинхрон —
  ловушка git-ворктри (дефолт `:6003` — прокси основного дерева) — красит
  прогон до первого теста с путями обеих баз.
- **Соло-режим GUI-тестов** (`solo_base`): GUI-тест и клиент 1c-db на одной
  файловой базе вешают друг друга — модуль с фикстурой идёт соло. Фикстура
  запрашивается параметром теста и ничего не отдаёт: перед первым тестом
  модуля клиенты базы гасятся (`--stop --base` скрипта контура
  `$DSH_1C_ROOT/scripts/start_1c_db.sh`; инстанс — по строке соединения своей
  записи в `db-instances.yaml`, mono — по привязке дерева), после модуля —
  включая падение по ассерту — возвращается клиент стенда: mono или
  `--instance`; клиента до гашения не было — восстановление ничего не
  поднимает. Канал инстанса берётся из url (`?channel=` — контур кладёт его
  в запись MCP `1c-db-<имя>`); инстанс с этим каналом ищется в
  `.dsh/1c/db-instances.yaml` (канал — поле `channel` записи или её имя),
  канал без инстанса — громкий отказ. Прокси фикстура не гасит и не
  поднимает (мёртвый прокси старт стенда поднимет сам — живой прокси
  остаётся предусловием среды, как у `onec_db`). Использование фикстуры
  хоть одним тестом модуля вешает на весь модуль маркер `e2e_solo`; деление
  выборки run_e2e на сессионные и соло-наборы по этому маркеру — юнит #56
  (тикет Т8), в прогоне обвязки появится там.
- **Финализация сеанса** (`pytest_sessionfinish`): клиенты, поднятые
  фикстурами плагина за сеанс (реестр заполняет соло-восстановление), гасятся в
  конце сеанса — и на зелёном, и на упавшем прогоне — правилом гашения
  контура (короткие одиночные kill + перепроверка `/proc`, добивание по
  pid). Перечень — реестр подъёмов (pid — из контракта вывода скрипта
  «• клиент запущен (pid N)»; подъём без этой строки — громкое
  предупреждение, такого клиента финализация не знает); перед kill
  плагин сверяет `File=` в cmdline — чужой процесс под переиспользованным
  pid не гасится. Клиент, поднятый не фикстурами плагина (GUI-клиент
  testpilot, ручной старт), сеансу не принадлежит — его гасят
  `--stop --base`; сирот снимает старт контура (гигиена старта), зомби-
  прокси — его автопочинка. Живой немаркированный клиент — граница гигиены:
  старт отказывает stand-гардом с pid, его гасят `--stop --base`. Прокси финализация не гасит никогда (общий на
  проект); kill -9 самого pytest финализацию не выполняет — эти остатки
  тоже снимет старт.
- **Диагностика канала** (`onec_db`): канал не отвечает — к ошибке
  дописывается состояние стенда блоком `start_1c_db.sh --status`: процессы
  с базой в cmdline (Usr/Pwd маскированы), владелец порта (`ss`), лок
  `1Cv8.1CL`, stand-замок. Сборка одна — у пакета контура; своя копия в
  плагине не заводится. Нет `DSH_1C_ROOT`/скрипта, упал или не уложился в
  потолок (`ONEC_DB_STATUS_TIMEOUT`, дефолт 60 с; сбитое значение названо
  в stderr) — ошибка называет пробел,
  исходная причина недоступности канала остаётся. Интерактивно тот же блок:
  `bash "$DSH_1C_ROOT/scripts/start_1c_db.sh" <корень> --status`.
- **Безопасность**: тестовый прокси разрешает `Записать`/`Удалить` (данные
  фикстур); COM, файловые операции, монопольный/привилегированный режимы
  заблокированы. В прод-контуре execute_code блокируется гейтом
  [1C-DSH](https://github.com/ntin60775/1C-DSH) — фикстуры только для
  тестовых деревьев.

## Зависимости

Единственная внешняя точка — MCP-сервер `1c-db` (прокси `onec_mcp_toolkit_proxy`,
поднимается скриптом контура `start_1c_db.sh` вместе с клиентом 1С).
От testpilot, unica и ZCode-хоста пакет не зависит.

## Разработка

```bash
python -m venv .venv && .venv/bin/pip install -e . pytest
.venv/bin/python -m pytest tests/ -q
```

Тесты — против фейкового MCP-сервера (handshake, tools/call, семантика
сериализатора) и процессами: `test_solo_base.py` и `test_session_finish.py`
гоняют pytest-сеансы подпроцессами с фейковым скриптом контура, настоящими
спящими процессами и чтением `/proc` — Linux с bash; живая проверка на
стенде 1С описана в контуре 1C-DSH.
